## 3줄 요약

- 테슬라처럼 스마트폰처럼 굴러가는 소프트웨어 정의 차량(SDV) 만든다고 100개 ECU 다이어트 시작했다가 부품사 갑을관계에 막혀 야근 시작됨
- 구식 CAN 통신 버스 걷어내고 기가비트 이더넷 깔았더니 스위치 패킷 라우팅 지연으로 에어백 센서 신호가 밀리는 공포 체험함
- 조널 제어기 4대로 차체 구석구석 배선은 줄였지만 수백만 줄의 레거시 C언어 오토사(AUTOSAR) 코드 통합하다 개발팀 야근 확정됨

## 뱀 둥지 와이어링 하네스 vs 중앙 집중형 조널 아키텍처

| 비교 항목 | 고전 도메인 분산형 (기존 내연기관차) | 조널(Zonal) 집중형 아키텍처 (최신 SDV) |
| :--- | :--- | :--- |
| **차내 ECU 수** | 80개~120개 (문짝 하나마다 제어기 하나씩 박힘) | 고성능 중앙 컴퓨터(HPC) 2개 + 4개 조널 제어기 |
| **와이어링 하네스** | 구리 전선 총길이 3~5km (무게만 50kg 이상) | 구역별 이더넷 백본으로 단순화 (무게 30% 절감) |
| **OTA 무선 업데이트** | 내비게이션 지도나 겨우 바꾸고 센터 방문 유도 | 모터 제어기, 서스펜션 댐핑까지 집 주차장에서 패치 |
| **소프트웨어 통합** | 부품 티어1 업체가 던져준 블랙박스 바이너리 | 리눅스/QNX 기반 단일 OS 위에서 가상화 컨테이너 구동 |

## SDV 개발 현장에서 엔지니어가 절망하는 3대 복병

1. **티어 1 부품사들의 블랙박스 C코드 사수전**
   - 구동계, 제동계 부품사들이 "영업비밀"이라며 소스코드 안 주고 컴파일된 C언어 바이너리만 툭 던져줌
   - 조널 컴퓨터 하나에 이 수십 개 외계 바이너리를 가상화(Hypervisor)로 묶어 돌리려니 메모리 충돌 나고 비상이 걸림
2. **차량용 이더넷(100BASE-T1)의 실시간 결정론(Determinism) 붕괴**
   - 넉넉한 대역폭 믿고 카메라와 라이다 데이터 쏟아부었더니 이더넷 스위치 버퍼가 가득 차 패킷 드랍 발생함
   - 시간 민감형 네트워크(TSN, Time-Sensitive Networking) 스케줄링 조금만 삐끗해도 조향 제어 신호가 5ms 밀려 식은땀이 흐름
3. **주차장 OTA 벽돌(Bricking) 참사의 공포**
   - 새벽 2시에 배터리 관리 시스템(BMS) 펌웨어 OTA 쐈다가 전압 강하 걸려서 차 전원 안 켜지면 렉카차 불러야 함
   - A/B 듀얼 뱅크 플래시 메모리 롤백 시스템 완벽히 안 짜두면 대표이사가 새벽에 핫라인 호출함

## 커뮤니티 반응

- **OTA 이후 주차장 먹통 렉카행 썰**: 밤새 소프트웨어 업데이트 돌려놓고 출근하려는데 도어락도 안 열려서 견인차 불러 윈도우 깨고 들어갔다는 생생한 실패담
- **이더넷 패킷 디버깅의 고통**: 옛날 CAN 버스는 오실로스코프로 찍으면 바로 전압 파형 나왔는데, 암호화된 이더넷 스위치 패킷 스니핑하느라 Wireshark 붙잡고 밤새웠다는 임베디드 엔지니어들의 탄식
- **완성차 소프트웨어 직영화 피로도**: 실리콘밸리 테슬라 흉내 낸다고 수천 명의 소프트웨어 인력 뽑아놓고 레거시 전장 규격 맞추다 번아웃 왔다는 완성차 내부 고발

## Q&A 또 궁금한 것은?

- **Q. SDV 되면 내 차도 자고 일어나면 성능이 빨라짐?**
  - 모터 인버터와 서스펜션 제어 알고리즘이 중앙 컴퓨터에 연결되어 있으면 가속력이나 코너링 감각이 소프트웨어 패치로 바뀜. 단 제조사가 유료 구독제로 인질 잡을 확률 99%임
- **Q. 구형 CAN 통신은 완전히 사라짐?**
  - 아님. 창문 모터나 사이드미러 접는 단순 액추에이터는 저렴하고 검증된 CAN이나 LIN 통신으로 조널 제어기 끝단에 여전히 거미줄처럼 붙어있음
- **Q. 차량용 이더넷은 PC 랜선이랑 똑같은 규격임?**
  - PC용 8가닥 RJ45 랜선 쓰면 차체 진동으로 1달 만에 헐거워짐. 차량용은 구리선 딱 2가닥을 꼬아놓은 단일 연선(Single-Pair Ethernet)에 전자기 노이즈 억제 쉴드를 둘러서 씀
