## 3줄 요약

- 기존 LLM이 직관으로 말 뱉는 시스템 1(Fast Thinking)이었다면, 최신 추론 모델은 스스로 생각하고 검증하는 **시스템 2(Slow Thinking)** 임.
- 모델 파라미터만 키우던 사전학습 스케일링 한계 부딪히자, 추론 단계 연산량(Test-time Compute)을 쏟아붓는 방식으로 패러다임 전환됨.
- 복잡한 수식, 알고리즘 구현, 논리 퍼즐 풀 때 할루시네이션 잡는 유일한 탈출구임.

---

## Test-time Compute 핵심 메커니즘 3가지

1. **숨겨진 사고 사슬 (Hidden Chain-of-Thought)**
   - 유저한테 최종 답변 주기 전에 모델 내부에서 스스로 가설 세우고 반론 제기함.
   - 중간 계산 과정에서 논리적 비약 생기면 자체적으로 백트래킹(Backtracking) 수행함.

2. **트리 탐색 & 프로세스 보상 모델 (PRM)**
   - 바둑의 몬테카를로 트리 탐색(MCTS)처럼 유망한 풀이 경로만 골라서 깊게 탐색함.
   - 최종 정답뿐 아니라 '풀이의 각 단계'마다 보상 점수를 매겨 최적 경로로 수렴시킴.

3. **토큰 소모량과 추론 성능의 비례 법칙**
   - 질문이 쉬우면(단순 번역 등) 100토큰 내로 즉시 출력함.
   - 문제 꼬여있으면 내부적으로 수천 토큰씩 연산 돌리면서 정답률을 끌어올림.

## 전통적 LLM vs 추론 전용 모델 비교

| 비교 항목 | 전통적 범용 LLM (GPT-4o 등) | 추론 전용 모델 (o1 / o3 / R1) |
| :--- | :--- | :--- |
| **사고 체계** | 직관적 패턴 매칭 (시스템 1) | 숙고적 검증 및 백트래킹 (시스템 2) |
| **응답 지연(TTFT)** | 첫 토큰 0.2~0.5초 (초고속) | 내부 생각 완료까지 5~30초 소요 |
| **적합한 업무** | 일반 번역, 카피라이팅, 요약, 단순 챗 | 난해한 수학 증명, 보안 취약점 감사, 대형 버그 수정 |
| **비용 효율** | 토큰당 단가 저렴, 빠른 처리 | 질문 1개당 내부 생성 토큰 많아 단가 높음 |

## 실무 적용 가이드
- 단순 챗봇이나 FAQ 응대에 추론 모델 물리면 비용 폭탄 맞고 유저 이탈함.
- **코드 생성, 아키텍처 리뷰, 데이터 분석 SQL 생성**처럼 "틀리면 큰일 나는 작업"에만 핀포인트로 투입하는 게 정석임.
