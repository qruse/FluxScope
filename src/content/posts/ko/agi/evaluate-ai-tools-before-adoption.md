## 3줄 요약

- 벤더사 영업맨이 들고 온 "MMLU 90점" PPT 장표에 홀려 결제했다간 사내 세무 규정 엣지 케이스에서 14개 오답 내고 감옥 갈 수 있음
- 공개 리더보드는 올림피아드 입상 자랑일 뿐, 우리 회사 레거시 DB와 누더기 업무 규칙 앞에서는 영락없는 헛똑똑이 됨
- 모델한테 전권 쥐여주지 말고 사람 손 거치는 인간 검토(HITL) 게이트 안 걸면 사고 터지고 대표이사 호출행 확정임

---

## 벤더 과장 광고 거르고 모델 성능 검증하는 5단계 체크리스트

1. **마케팅팀의 "업무 혁신" 뜬구름부터 칼같이 쳐내기**
   - ❌ "AI 도입해서 CS 효율 500% 극대화하기" (측정 불가, 슬라이드 발표용 헛소리)
   - ⭕ "고객 불만 티켓 읽고 ERP 환불 규정 조항 번호 정확히 인용해 3줄 요약 뽑기" (단칼에 정오 판정 가능)
   - 업무 범위 좁게 안 쪼개면 모델이 환각으로 지어낸 가짜 규정 믿고 환불금 마구 퍼주게 됨

2. **정상 데이터 대신 극한의 함정 케이스 30개로 몰아붙이기**
   - 정상 케이스 10개: 평소 들어오는 뻔한 질문 (여기서 틀리면 모델 깃허브 삭제해야 함)
   - 정보 누락 케이스 10개: 영수증 금액 찢어놓고 모델이 "금액 안 보여요" 되묻는지 확인 (보통은 뻔뻔하게 숫자 지어냄)
   - 함정 케이스 10개: 사내 보안 규정상 "답변 불가"라고 거절해야 정상인 데이터 (90% 확률로 벤더 모델이 보안 기밀 술술 불어버림)

3. **"AI가 알아서 잘해요" 대신 초안 교정에 몇 분 버리는지 재기**
   - 생성 속도가 1초면 뭐함, 헛소리 교정하느라 시니어 개발자가 30분 동안 머리 쥐어뜯으면 마이너스 생산성임
   - 측정 공식: `(사람이 처음부터 쌩으로 짠 시간) - (AI 초안 + 인간 검수 및 뒷수습 시간)`
   - 이 값이 음수 나오는 순간 그 모델은 도입 즉시 라이선스 해지해야 평화가 찾아옴

4. **모델이 헛소리한 흑역사는 스프레드시트에 영구 박제하기**
   - 입력 프롬프트, 참조 문서, 모델의 창의적인 헛소리, 기대 정답을 박제함
   - 벤더사가 "새 버전 나왔으니 더 똑똑해졌습니다"하고 업데이트 칠 때마다 이 테스트셋 그대로 돌려서 회귀 테스트(Regression Test)로 철저히 검증해야 함

5. **사고 시 치명적 리스크가 걸린 작업엔 무조건 사람 검토(HITL) 걸기**
   - 사내 직원용 식단표 요약 같은 건 모델 혼자 놀게 둬도 됨
   - 법률 계약서, 세무 보고서, 환불 승인 버튼은 모델 출력 뒤에 인간 승인 도장 찍는 [NIST AI RMF](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/) 방화벽 안 치면 사고 즉시 전원 징계위원회 회부됨

## 커뮤니티 반응

- **리더보드 점수 맹신에 대한 회의론**: 공개 벤치마크 1등 찍은 모델 모셔왔더니 사내 슬랙 질문 3개 만에 밑천 드러내고 뻗었다는 현장 엔지니어들의 울분 폭발
- **골든 데이터셋 관리 피로도**: 처음엔 야심 차게 엣지 케이스 50개 모았는데 분기마다 비즈니스 로직 바뀌면 데이터셋 업데이트하다가 야근 확정이라는 실무 고충
- **LLM-as-a-Judge 편향성 성토**: 채점관으로 세워둔 LLM이 자기랑 문체 비슷하거나 말 길게 늘어놓는 모델한테 만점 주는 자화자찬 쇼에 헛웃음 나온다는 평가

## Q&A 또 궁금한 것은?

- **Q. 글로벌 1위 벤치마크 모델인데 우리 회사에 바로 꽂아도 됨?**
  - 절대 안 됨. 올림피아드 금메달리스트를 동네 분식집 재고 관리에 데려다 놓으면 떡볶이 떡 세다가 환각으로 소설 씀
- **Q. 테스트 케이스는 처음부터 1,000개쯤 파야 됨?**
  - 그러다 데이터 모으다 지쳐서 프로젝트 접음. 진짜 자주 터지는 치명적 지뢰 20~30개로 털어보는 게 가성비 최고임
- **Q. 테스트셋 한번 통과하면 끝임?**
  - 벤더사가 몰래 가중치 미세조정하거나 프롬프트 쉼표 하나 바뀔 때마다 오답 터지므로 주기적 회귀 테스트 안 돌리면 뒷감당 안 됨
