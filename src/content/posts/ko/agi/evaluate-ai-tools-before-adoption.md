## 3줄 요약

- 화려한 벤더사 데모에 낚이지 말고, **실제 업무 딱 1개**만 떼와서 검증해야 함
- 정상 케이스 말고 일부러 꼬아둔 예외/함정 케이스 30개로 스트레스 테스트 치는 게 핵심임
- 모델이 헛소리했을 때 타격 큰 작업은 무조건 인간 검토(Human-in-the-loop) 게이트 걸어둬야 함

---

## 실전 검증 5단계 체크리스트

1. **태스크부터 칼같이 정의함**
   - ❌ "CS 업무 빠르게 만들기" (측정 불가)
   - ⭕ "티켓 본문 읽고 근거 링크 달린 3줄 요약 및 액션 아이템 추출" (측정 가능)
   - 입력 데이터, 필수 출력 포맷, 실제 사용할 유저를 1장짜리 스펙으로 문서화함

2. **테스트셋 30개 선별 (일부러 꼬아두기)**
   - 정상 케이스 10개: 평소 들어오는 표준 요청
   - 모호/누락 케이스 10개: 필수 정보 빠진 상태에서 모델이 되묻는지 확인
   - 함정 케이스 10개: 모델이 모른다고(답변 불가) 선언해야 정상인 데이터
   - MMLU 같은 공개 벤치마크 점수는 사내 도메인이나 보안 규정 못 거르므로 맹신 금지

3. **정량 평가 지표 셋업**
   - **사실 일치율**: 레퍼런스 문서 대비 환각(할루시네이션) 발생률 측정
   - **엔드투엔드 소요 시간**: 초안 생성 + 실무자 최종 검토/수정까지 총합 시간
   - **수정 비용**: 모델 오답 고치는 데 실무자가 쏟는 리소스 산출

4. **실패 케이스 아카이빙 (회귀 테스트용)**
   - 입력 프롬프트, 참조 원본, 모델 오답, 기대 정답을 스프레드시트에 박제함
   - 모델 버전 올라가거나 프롬프트 고칠 때마다 동일 데이터셋으로 회귀 테스트(Regression Test) 돌림

5. **인간 검토(HITL) 마지노선 긋기**
   - 엔드유저에게 바로 쏴도 되는 영역과 내부 검토 거쳐야 하는 영역 경계 확정
   - [NIST AI RMF](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/) 기준 거버넌스·측정·관리 사이클을 상시 운영 프로세스로 내재화함

## 실무 평가지표 비교표

| 평가 항목 | 추천 지표 (실무형) | 비추천 지표 (위험함) |
| :--- | :--- | :--- |
| **정확도** | 사내 근거 문서 기반 사실 일치율 (%) | 단순 공공 벤치마크 점수 (사내 데이터 반영 X) |
| **효율성** | 초안 생성부터 사람 최종 교정까지 총 소요 시간 | 생성된 토큰 수나 텍스트의 절대적 길이 |
| **안전성** | 오류 발생 시 실무자 발견 및 교정 소요 시간 | 오류가 0%일 것이라는 비현실적 전제 |

## Q&A 또 궁금한 것은?

- **Q. 유명 벤치마크 1등 모델이면 검증 없이 바로 써도 됨?**
  - 안 됨. 벤치마크는 수능 점수 같은 거라 사내 특화 용어나 비즈니스 로직 검증 못 함
- **Q. 파일럿 테스트용 데이터는 몇 개나 준비해야 됨?**
  - 처음부터 수백 개 팔 필요 전혀 없음. 고품질 20~30개로 실패 패턴 잡는 게 훨씬 효율적임
- **Q. 테스트는 언제 다시 돌려야 됨?**
  - 프롬프트 수정, 모델 파라미터 변경, 업무 포맷 바뀔 때마다 기존 테스트셋 재실행 필수임
