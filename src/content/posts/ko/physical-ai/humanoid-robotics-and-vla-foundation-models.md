## 3줄 요약

- 역기구학 수식과 좌표 하드코딩 대신 카메라 영상과 텍스트 지시를 모터 제어 토큰으로 직접 변환함
- RT-2, OpenVLA 등 대형 멀티모달 모델이 관절 각도(Action Chunk)를 연속 토큰으로 자동 디코딩함
- 시뮬레이션(Sim2Real) 간극과 50Hz 이상 고주파 실시간 물리 제어 루프 유지가 최대 기술 난제임

## 전통적 기구학 로봇 제어 vs VLA 파운데이션 모델

| 비교 항목 | 고전 기구학 제어 (Classical Kinematics) | VLA 파운데이션 모델 (OpenVLA / RT-2) |
| :--- | :--- | :--- |
| **명령 해석** | "X: 30cm, Y: 15cm 이동 후 그리퍼 닫기" 좌표 수동 주입 | "테이블 위 사과 집어서 바구니에 담아" 자연어 직관 입력 |
| **객체 일반화** | 등록되지 않은 새로운 컵이나 과일 모양은 잡지 못함 | 인터넷 대규모 이미지 학습 덕분에 미지의 물체도 형태 유추 |
| **제어 파이프라인** | 인지(비전) $\to$ 3D 점군 생성 $\to$ 역기구학 연산 $\to$ PID 모터 | 카메라 토큰 + 텍스트 토큰 $\to$ 트랜스포머 $\to$ 관절 각도 토큰 |
| **환경 변화 적응** | 조명, 배경 천 색상 조금만 바뀌어도 좌표 오류 발생 | 의미론적(Semantic) 공간 이해력으로 조명 변화에 상대적 강건 |

## VLA 상용화를 가로막는 3대 물리 제약

1. **추론 속도와 제어 주기(Control Frequency)의 괴리**
   - 7B~13B 거대 VLA 모델의 순방향 추론은 NPU에서 5~10Hz 수준에 불과함
   - 로봇이 넘어지지 않고 물건을 쥐려면 최소 50~200Hz 모터 토크 보정 루프가 필수라 계층형 액션 청킹(Action Chunking) 구조 필요함
2. **실물 데이터 수집 비용(Embodied Data Bottleneck)**
   - 텍스트 데이터는 웹 크롤링이 가능하지만 로봇 파지 데이터는 비싼 VR 원격 조작으로 사람이 일일이 수집해야 함
3. **접촉 물리(Contact Mechanics) 오차**
   - 두 손가락 그리퍼와 달리 5지 다관절 핸드는 미끄러짐 마찰 계수와 탄성 변형이 비선형적이라 센서 피드백 없으면 물건 부숨

## 커뮤니티 반응

- **데모 영상 편집에 대한 회의적 시각**: 벤처 로봇 기업들이 공개하는 완벽한 설거지나 빨래 영상이 수십 번 실패 끝에 건진 원테이크 편집본이라는 로보틱스 연구자들의 냉정한 지적
- **하드웨어 내구성 및 정비 한계**: 100시간 이상 연속 가동 시 감속기 기어 마모와 케이블 단선으로 유지보수 비용이 소프트웨어 개발비보다 더 든다는 현장 피드백
- **데이터 파운데이션 부족 현실**: 언어나 비전과 달리 체화(Embodied) 로봇 데이터는 인터넷 크롤링이 불가능해 데이터 병목이 물리 AI 도달의 최대 장애물이라는 공감대

## Q&A 또 궁금한 것은?

- **Q. 시뮬레이터(Issac Sim 등)에서 학습시킨 정책이 실물 로봇에서 바로 돎?**
  - 안 됨. 시뮬레이션 물리 엔진과 실물 모터 백래시, 마찰력 차이(Sim2Real Gap)가 커서 도메인 랜덤화(Domain Randomization)와 실물 미세조정 필수임
- **Q. 휴머노이드 로봇 본체에 거대 GPU를 다 싣고 다닐 수 있음?**
  - 불가능함. 배터리 소모와 발열 한계 때문에 상위 계획(VLA 모델)은 온보드 소형 엣지 칩이나 로컬 Wi-Fi 서버에서 5Hz로 돌리고, 하위 모터 밸런싱만 마이크로컨트롤러가 500Hz로 전담함
- **Q. 액션 청킹(Action Chunking)이 구체적으로 뭐임?**
  - 모델이 한 번 생각할 때 다음 1개의 모터 각도만 뱉지 않고, 향후 1~2초간의 연속된 궤적(예: 30개 타임스텝)을 한 덩어리로 출력해 제어 지연을 상쇄하는 기술임
