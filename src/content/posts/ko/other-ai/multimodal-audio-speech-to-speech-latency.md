## 3줄 요약

- STT로 받아 적고 LLM이 묵념하고 TTS로 읽어주던 3단계 릴레이는 아무리 쥐어짜도 1.8초 동안 어색한 정적이 흘렀음
- 오디오 파형을 토큰으로 다이렉트 처리하는 네이티브 모델로 갈아타자 310ms 만에 숨소리까지 섞인 즉각 맞장구 완성됨
- 단, 유저가 말하다 숨 한 번 들이켰을 뿐인데 말 끊고 불쑥 끼어드는 눈치 없는 AI와 4배 폭증한 서버 비용은 덤임

---

## 굼벵이 3단 릴레이 vs 입술 떼자마자 맞받아치는 네이티브 S2S

| 비교 항목 | 고전 3단 릴레이 (Whisper + LLM + TTS) | 네이티브 Speech-to-Speech (GPT-4o Voice 등) |
| :--- | :--- | :--- |
| **체감 지연 시간** | 1.8초~2.5초 (어색해서 마른침 꼴깍 삼킴) | 250ms~350ms (말 끝나기 무섭게 즉시 받아침) |
| **감정 및 뉘앙스** | 텍스트로 치환되면서 한숨, 비꼼, 울먹임 전멸 | 억양 토큰 살아있어 속삭임과 능글맞은 웃음까지 재현 |
| **말끊기(Barge-in)** | 말하는 도중 끊으면 기계음 뚝 끊기며 에러 뿜음 | 모델이 듣는 동시에 생각해서 사람처럼 자연스레 양보함 |
| **서버 관리 지옥도** | 3개 서버 따로 띄우고 큐 관리하느라 주말 증발 | 모델 1개로 끝나지만 WebRTC 실시간 세션 유지로 멘탈 터짐 |

## 300ms 사수하려다 인프라팀 쓰러지는 3대 엔지니어링

1. **24kHz 오디오를 쥐어짜는 뉴럴 오디오 코덱**
   - 쌩 오디오 데이터를 모델에 밀어 넣었다간 GPU가 질식사함
   - EnCodec, SNAC 같은 신경망 압축기로 초당 수십 개 이산(Discrete) 토큰으로 찌그러뜨려 전송해야 대역폭 방어함
2. **첫 글자 나오자마자 입 털기 (스트리밍 청크 디코딩)**
   - 문장 끝날 때까지 기다리지 않고, 첫 음향 토큰 5개 뽑히자마자 스피커로 소리 쏴주는 얌체 기술 필수임
3. **편안했던 HTTP 버리고 WebRTC 진흙탕으로 다이빙**
   - REST API 시절의 평화는 끝남. 40ms 이하 패킷 왕복 사수하려고 UDP 기반 전이중(Full-Duplex) WebRTC 뚫다가 개발자 탈모 옴

## 커뮤니티 반응

- **말 끊고 끼어드는 무례함 성토**: 유저가 말하다가 0.3초 숨 고르고 다음 단어 생각하는데, "네 말씀하세요!"라며 칼같이 말 잘라먹는 AI 때문에 혈압 오른다는 후기 다수
- **WebRTC 실시간 세션 유지비 폭탄**: 기존 무상태(Stateless) API는 대충 로드밸런서 붙이면 끝났지만, 수만 명의 양방향 오디오 파이프라인 상시 유지하느라 클라우드 네트워크 비용 폭발
- **기계음 TTS의 완전한 퇴출 환호**: 텍스트 번역기 특유의 로봇 말투에서 벗어나, 진짜 콜센터 베테랑 상담원처럼 능청스럽게 맞장구치는 감정 표현력에는 만장일치 감탄

## Q&A 또 궁금한 것은?

- **Q. 유저가 말하는 도중에 왜 자꾸 지 혼자 끼어듦?**
  - 말끝 억양이 내려가는지(문장 종결) 올라가는지(접속사) 판별하는 턴테이킹(Turn-taking) 헤드가 오작동해서 그럼. 침묵 임계값(Threshold)을 500ms 이상으로 여유 있게 벌려줘야 눈치 챙김
- **Q. 텍스트 챗봇보다 API 비용 얼마나 더 나옴?**
  - 음성은 초당 50개 안팎의 오디오 토큰을 끊임없이 쏟아냄. 텍스트 대비 최소 4배 이상 법인카드가 빠르게 녹아내리니 결제 한도부터 늘려놔야 함
- **Q. 카페나 지하철에서 쓰면 왜 헛소리함?**
  - 네이티브 모델은 주변 소음까지 말소리로 착각하고 대답함. 단말기 앞단에 딥러닝 기반 잡음 제거(DeepFilterNet) 레이어 안 박으면 지하철 안내방송에 혼자 대답하고 난리 남
