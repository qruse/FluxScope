## 3줄 요약

- 클라우드 API 호출 없이 비행기 모드에서도 초당 35토큰 속도로 동작하는 온디바이스 AI 시대 진입함
- 4-bit 양자화(AWQ/GGUF) 적용 시 3B 모델 VRAM 점유율을 1.8GB 수준으로 압축해 일반 폰에서도 구동 가능함
- 발열로 인한 AP 쓰로틀링과 복잡한 멀티스텝 추론 시의 할루시네이션이 여전한 실무적 장벽임

## 클라우드 거대 모델 vs 온디바이스 소형 모델(sLM)

| 비교 항목 | 클라우드 LLM (70B+ 파라미터) | 온디바이스 sLM (1B~3B 파라미터) |
| :--- | :--- | :--- |
| **운영 인프라** | 거대 데이터센터 H100/B200 클러스터 | 스마트폰, 태블릿, 로컬 NPU 및 통합 메모리 |
| **네트워크 의존성** | 오프라인 환경 작동 불가 (Wi-Fi/5G 필수) | 100% 에어갭 오프라인 로컬 추론 가능 |
| **개인정보 보호** | 프라이빗 데이터가 외부 서버로 전송됨 | 단말기 밖으로 단 1바이트도 유출되지 않음 |
| **복잡 추론 능력** | 다단계 코딩, 논문 분석, 수식 증명 탁월함 | 단순 요약, 개체명 추출(NER), 문장 교정에 한정 |

## 온디바이스 배포 3대 병목 극복 전략

1. **양자화 손실 최소화 (AWQ vs RTN)**
   - 가중치 전체를 단순 절삭(RTN)하면 성능이 붕괴되므로, 활성화 이상치(Activation Outlier)를 보호하는 AWQ 방식 필수 적용
2. **KV 캐시 VRAM 점유율 통제**
   - 폰 메모리는 OS 및 다른 앱과 공유하므로 컨텍스트 윈도우를 2,048 토큰 이내로 캡핑하고 슬라이딩 윈도우 적용
3. **발열 및 배터리 방전(Thermal Throttling)**
   - NPU 풀로드가 2분 이상 지속되면 단말 표면 온도가 45도에 육박하므로, 백그라운드 배치 추론 시 시간당 쿼리 상한 강제해야 함

## 커뮤니티 반응

- **OOM 크래시와 OS 백그라운드 킬 고충**: 3B 모델 로드까지는 성공해도 사용자가 카메라나 게임 켜는 순간 OS가 AI 앱을 메모리 부족으로 바로 강제 종료한다는 모바일 개발자들의 하소연
- **양자화 품질 저하 체감**: 벤치마크 점수는 4-bit에서도 멀쩡해 보이는데 실제 한국어나 복잡한 지시문 추종에서는 반복 루프에 빠진다는 실무 피드백
- **비용 제로와 오프라인 보안성에 대한 절대적 선호**: 클라우드 API 호출 요금과 개인정보 유출 걱정 없이 단말 내에서 로컬로 도는 독립성에 대해서는 개발자와 엔드유저 모두 극찬

## Q&A 또 궁금한 것은?

- **Q. 스마트폰에서 7B 이상 모델도 돌릴 수 있음?**
  - 메모리 16GB 탑재 최신 플래그십 기기에서는 구동 가능하나, OS가 앱 메모리를 4GB 이상 쓰면 강제 종료(OOM Kill)시키는 제약이 있어 실질적 상한선은 3B 모델임
- **Q. 한국어 성능도 4-bit 양자화 상태에서 유지됨?**
  - 영어 중심 사전학습 모델은 양자화 시 한국어 토크나이저 효율이 떨어져 횡설수설함. 한국어 토큰 코퍼스가 20% 이상 섞인 모델을 베이스로 써야 함
- **Q. NPU vs 모바일 GPU 중 어디에 올리는 게 전력에 유리함?**
  - NPU가 동일 연산량 대비 전력 소모(TOPS/W)가 GPU 대비 2.5~3배 우수하므로, NPU 전용 런타임(Qualcomm QNN, Apple CoreML) 컴파일이 무조건 유리함
